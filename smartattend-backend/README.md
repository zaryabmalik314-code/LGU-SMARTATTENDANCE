# SmartAttend Backend

FastAPI backend for GPS geofencing + face recognition faculty attendance.

## Structure
```
app/
  main.py         - routes
  models.py       - SQLAlchemy models (Faculty, AttendanceRecord)
  schemas.py      - Pydantic request/response models
  database.py     - DB session (SQLite local / Postgres on Railway)
  geofence.py     - polygon ray-casting + GPS accuracy handling
  face_verify.py  - server-side face detection + embedding (InsightFace/ArcFace) + matching
requirements.txt
Procfile          - for Railway
```

## Local run
```
pip install -r requirements.txt --break-system-packages
uvicorn app.main:app --reload
```
Visit http://localhost:8000/docs for interactive API docs (auto-generated by FastAPI).

First run will download the InsightFace `buffalo_l` model bundle (~280MB) to
`~/.insightface/models/` — needs outbound network access. On Railway this
happens once per fresh deploy (cached in the container after that), so the
first request after a deploy will be slower.

## Before deploying
1. **Fill in `CAMPUS_BOUNDARY`** in `app/geofence.py` with your real 16-point polygon from SCEMS.
2. **Tune `FACE_MATCH_THRESHOLD`** in `app/face_verify.py` once you have real faculty enrollment data — 0.50 is a starting point for ArcFace cosine similarity, not gospel. Test with real faculty photos across lighting/angle variance before locking it in.
3. **Lock down CORS** in `main.py` (`allow_origins=["*"]` → your actual frontend domain).
4. On Railway: add a Postgres plugin, it auto-injects `DATABASE_URL`. No code changes needed — `database.py` already handles it.

## Frontend integration notes — face capture (updated)
Face embedding now happens **server-side** (InsightFace/ArcFace), not in the
browser. The frontend's job is just to capture and pre-filter frames — no
face-api.js embedding step needed anymore.

- **Enrollment / re-enrollment** (`/api/faculty/enroll`, `/api/auth/re-enroll-face`):
  record a ~5s video, bucket frames by yaw angle (left/center/right), pick
  the best frame per bucket client-side, send up to 3 base64 frames as
  `face_images`. Backend embeds each independently and stores all 3.
- **Check-in / check-out** (`/api/attendance/check-in`, `/api/attendance/check-out`):
  record a short video, client-side filter for blur/quality, send a handful
  of candidate frames as `face_images` (base64, with or without a `data:`
  URL prefix). Backend picks the single best frame (detection confidence ×
  size × frontal-ness) and compares against all 3 stored angle embeddings,
  taking the max similarity.
- Send **3-5 GPS readings** taken over ~5-10 seconds to `/api/attendance/check-in`, not just one. Backend picks the most accurate.
- Optionally send `wifi_ssid` as a secondary "on campus" signal (frontend would need to read this via a native wrapper/TWA, not plain browser JS — browsers can't read WiFi SSID directly for privacy reasons. Worth checking if your PWA-to-APK wrapper exposes it.)

## Endpoints
- `POST /api/faculty/enroll` — enroll faculty with name/email/face embedding
- `GET /api/faculty` — list enrolled faculty
- `POST /api/attendance/check-in` — the main check-in flow (GPS + face verify)
- `GET /api/attendance?faculty_id=` — attendance history
